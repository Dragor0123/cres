# 000 — 야간 큐 운영 규칙 (2026-10-13 밤 ~ 10-14 아침)

사용자 부재 약 9시간. 이 파일은 002–009의 실행 순서, GPU 배치, 실패·게이트 처리를 정한다. CLAUDE.md와 충돌하면 **이 파일이 우선**(야간 한정).

## 1. 기본 원칙

- 사용자에게 묻지 않는다. CLAUDE.md §1의 "결정 필요 → 멈춤"은 야간에는 **"그 항목만 멈추고(skip) 다음 독립 항목으로 진행"**으로 바꾼다. 결정 필요 사항은 `reports/QUEUE_STATE.md`와 009 보고서에 모은다.
- 사전 등록(P##)과 게이트 기준은 실행 전에 커밋하고, 결과를 본 뒤 바꾸지 않는다.
- 지시서에 적힌 값은 **사용자 부재로 Claude가 정한 임시 기본값**이다(R002, R003). 아침에 사용자가 검토한다. 기본값을 바꾸지 말고, 바꿀 이유가 보이면 "결정 필요"에 적는다.

## 4. GPU·작업 실행

- GPU는 UUID로 지정: `nvidia-smi -L`로 확인해 `GPU-A`(0번), `GPU-B`(1번)를 `QUEUE_STATE.md`에 기록. `CUDA_VISIBLE_DEVICES=<UUID>`.
- 장시간 실행은 `tools/job_runner.py`(003에서 작성)로 띄운다: 작업 목록(jsonl)을 GPU별로 순차 실행, `nohup`, 작업마다 로그·종료 코드·소요 시간 기록, 끝난 작업은 `done` 표시. 같은 작업 목록을 다시 넣어도 `done`은 건너뛴다.
- 동시 실행: 기본 **GPU당 1개**. 003에서 단일 실행의 GPU 사용률·메모리를 재서 사용률 < 40%이고 메모리 < 8 GB이면 GPU당 2개까지 허용. 결정과 근거 수치를 `QUEUE_STATE.md`에 기록.
- 프로세스당 seed 하나.
- 기다릴 때는 `sleep 600` 단위로 확인한다(빈 루프 금지).

## 5. 시간 예산과 축소 규칙

- 시작 시각 T0를 `date`로 기록. 각 항목 시작·종료 시각도 기록.
- 003에서 단일 실행 시간을 측정한 뒤, 남은 sweep 전체의 예상 종료 시각을 계산해 기록.
- 예상 종료가 T0+8h를 넘으면 아래 순서로 줄인다(위부터 먼저 버림):
  1. 007 TEG-orig 공식 실행
  2. 008·006의 K=5 (K=1만 남김)
  3. 007 VISION의 K=5
  4. 006의 λ=0.5 (λ=1.0만 남김)
  관문(004·005)과 지도 단독 sweep은 줄이지 않는다.
- T0+8h00 이후 새 작업을 띄우지 않는다. T0+8h30에 009를 쓴다(돌고 있는 작업은 그대로 두고 목록만 기록).

## 6. 실패 처리

- 실행 실패: 같은 설정으로 1회 재시도(로그 `_retry1`, 기존 로그 덮어쓰기 금지). 다시 실패하면 `failed`로 기록하고 진행.
- 게이트 실패: 그 게이트에 의존하는 항목만 건너뛴다(G3 실패 → 006·008 skip, G1 또는 G2 실패 → 008 skip). 독립 항목은 계속.
- 코드 버그로 지시서를 끝낼 수 없으면: 30분 넘게 붙잡지 말고 상태를 기록한 뒤 다음 독립 항목으로.
- 디스크 여유 < 10 GB면 새 작업을 띄우지 않고 기록.

## 7. 기록과 백업 (서버는 곧 폐기됨)

- `results/`는 git 제외이고 서버와 함께 사라진다. 나중에 다시 계산할 수 있어야 하는 것은 **`records/`에 작은 CSV/JSON으로** 저장하고 커밋한다(002에서 규칙 정의).
- 항목 하나가 끝날 때마다: 보고서 작성 → `QUEUE_STATE.md` 갱신 → 커밋 → push. sweep 진행 중에도 1시간마다 `records/` 커밋·push.
- 강제 push, 히스토리 재작성 금지. refs·data 수정 금지.
