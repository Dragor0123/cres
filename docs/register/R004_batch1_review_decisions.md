# R004 1차 큐 검토 결정 (2026-10-14, 결정자: 이희태)

1. G3(003): 1차 불충족 → 이식 버그 수정 → 2차 충족 처리를 승인. 1차 실패 기록은 유지.
2. R002 평가 프로토콜: 임시 기본값을 확정으로 승격. seed 3–9 분할은 SE를 줄여야 할 때 사용 가능(TEG-choi와 같은 코드로 결정적으로 재현한 분할).
3. R003 CRES 설계값: "1차 큐에서 검증한 설계"로 기록 유지. 재설계 시 새 R 번호.
4. G1 불통과·G2 부분 통과 이후 방향: 순도가 정확도를 바꾸는지 먼저 직접 측정한다(013). CRES pilot은 탐색용으로만 실행(014).
5. 계산량을 맞춘 대조군(지도 에피소드 2개/스텝)을 추가한다(012).
6. NaQ 재구현: Feat·Diff 모두 유지. 에피소드 안 중복 노드 금지로 수정하고 재실행. K-shot support 구성은 원 NaQ 방식을 따른다. 풀 U(base 제외)는 유지하고, 전체 노드 풀은 참고용 한 줄로만.
7. VISION: venv 환경 승인. 비교 조건(레이블 없이 전체 노드로 학습, 기본 하이퍼파라미터)은 바꾸지 않고 표에 단서로 표기. 직접 비교한다.
8. TEG-orig 공식 실행: 유지하되 최저 우선순위(다른 작업이 모두 끝난 뒤).
9. r 방향(비대칭) 구현: 현행 유지(P03). 재설계 시 대칭화.
10. 순도 곡선 설계: A1(NaQ-Feat 에피소드에서 출발, 유사도 순 치환), B1 기본 + B2(way 사이 충돌 제거) 0% 한 점 추가.
